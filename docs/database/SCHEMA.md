# wavy: database schema

Postgres (Supabase) with 69 tables, 36 enums and 17 migrations in `supabase/migrations/`. The ERD is in [ERD.md](ERD.md). Related docs: [RBAC.md](RBAC.md), [INDEXING.md](INDEXING.md) and [PAYMENTS_DATA.md](PAYMENTS_DATA.md).

## Conventions

- Money is always **integer paise** (`integer`). ₹999 is stored as `99900`. Totals are computed server-side by `compute_pricing()`.
- IDs are `uuid default gen_random_uuid()`. Timestamps are `timestamptz`. Every table with `updated_at` has a `set_updated_at` trigger.
- Enum values match `src/types/domain.ts` exactly (`product_status`, `order_status`, `payment_status` and the rest).
- JSON that RPCs take and return uses **camelCase** keys, matching the domain types (`CartTotals`, `Address`, `offerNudges`). Stored address JSON (`orders.shipping_address`) uses the domain `Address` shape.
- **RLS is on for every table**, including the analytics partitions. See `0016_rls_policies.sql` and [RBAC.md](RBAC.md).
- Secrets are never stored. `payment_gateways.config` and `integration_configs.config` have CHECK constraints that reject secret-looking keys.
- Types: `src/types/database.ts` is generated by `npm run db:types` against a running local stack.
- Validation: run `supabase db reset` (local, needs Docker) or `supabase db push` to a hosted project.

## Tables

### Identity and RBAC
| Table | Purpose | Key columns / relations |
|---|---|---|
| profiles | 1:1 with `auth.users`, created by trigger on signup | `role user_role` (the effective role), `status`, email/phone/name. FK `auth.users.id` |
| permissions | Catalogue of capability codes | `code` PK such as `orders.refund` |
| role_permissions | Maps each role to its permissions (kept in sync with `permissions.ts`) | PK (role, permission) |
| staff_members | Staff invitation and lifecycle. A trigger sets `profiles.role` from it | email (unique, case-insensitive), `role`, `status invited/active/suspended`, `invited_by`, `user_id` |

### Catalog
| Table | Purpose | Key columns / relations |
|---|---|---|
| categories | Category tree | `parent_id` self-FK, slug, SEO columns, `is_active` |
| collections | Merchandising sets | slug, featured, start/end window, SEO |
| products | Sellable product | `category_id`, `status product_status`, descriptor/material/fit/care, `badges[]`, `try_on_enabled`. Trigger-maintained: `price_min/max`, `compare_at_min`, `rating_avg`, `review_count`. `search_vector` is a generated tsvector |
| collection_products | Many-to-many between products and collections | PK (collection_id, product_id), sort_order |
| product_variants | SKU level (colour × size) | `sku` unique, `color`, `color_hex`, `size`, `price`, `compare_at > price`, `status variant_status` (active/out_of_stock is automatic) |
| product_media | Images and video | `product_id`, optional `variant_id` or `color`, at most one primary per product |
| inventory | Stock for one variant | `on_hand`, `reserved`, generated `available`, `CHECK on_hand - reserved >= 0` |
| inventory_reservations | Holds while a customer pays | `order_id`, `status active/released/consumed/expired`, `expires_at` |
| inventory_movements | Append-only stock ledger | `reason`, `delta_on_hand`, `delta_reserved`, `*_after`, `reference_type/id`, `actor_id` |
| attributes / attribute_values / product_attribute_values | Facets such as material, silhouette and fit | `code`, `slug`. The product link table has a reverse index for filtering |
| related_products | Similar, related and complete-the-look links | PK (product, type, related), no self-links |
| wishlist_items | Customer wishlist | `user_id`, `product_id`, optional `variant_id` (unique, NULLS NOT DISTINCT) |

### Cart and checkout
| Table | Purpose | Key columns / relations |
|---|---|---|
| addresses | Saved customer addresses | `user_id`, Indian PIN code check, one default per user |
| shipping_zones | Groups of states with a default fallback zone | `states[]` (GIN index) |
| shipping_methods | Rates for each zone | `rate`, `free_above` (overrides the store threshold), `cod_available`, day range |
| carts | Cart for a signed-in user or an anonymous `session_id` | one active cart per user and per session, `coupon_code` |
| cart_items | Cart lines | `variant_id`, `quantity 1..10`, `unit_price_snapshot` (display only, set by trigger) |
| checkout_sessions | One per place-order intent | **`idempotency_key` unique**, contact/address, `quote` snapshot, `order_id` |

### Orders and payments (details in [PAYMENTS_DATA.md](PAYMENTS_DATA.md))
| Table | Purpose | Key columns / relations |
|---|---|---|
| orders | Immutable money and contact snapshot | `order_number wavy-100001…`, unique `idempotency_key`, `status`, `payment_status`, `subtotal/discount_total/shipping_total/cod_fee/tax_total/total` (a CHECK enforces the math and totals are immutable), `tax_rate` and `tax_inclusive` snapshot, coupon snapshot, `applied_discounts`, `pricing_snapshot`, **`tracking_token`** |
| order_items | Line snapshots | sku, name, colour, size, image, unit_price, quantity, `discount_allocated`, `line_total` |
| order_status_history | Every status transition, written by trigger | from/to, actor, actor_type, note |
| payment_gateways | Admin on/off switch for each provider | `provider` unique, `is_enabled`, `mode test/live`, `supported_methods[]`, non-secret `config` |
| payments | One series per (order, provider) | `status`, `amount`, `amount_captured/refunded`, `last_failure_*`. **Partial unique index: one successful payment per order** |
| payment_attempts | Each try | `attempt_no`, `provider_order_id/payment_id`, `method`, `failure_stage/source/code/reason`, `raw_request/response`. **One authorized/captured attempt per order.** A second capture is marked `duplicate` |
| payment_events | Every webhook and callback | **UNIQUE (provider, provider_event_id)**, `signature_valid`, `processing_status`, payload |
| refunds | Refunds | `payment_id`, optional `attempt_id` (duplicate capture) and `return_request_id`, unique `idempotency_key`. A trigger stops a refund from exceeding the captured amount |

### Shipping and returns
| Table | Purpose | Key columns / relations |
|---|---|---|
| shipments | Shiprocket shipments, both forward and return pickup | `awb` (unique), courier, `status shipment_status`, `eta`, `label_url`, `last_synced_at` |
| shipment_items | Which order lines are in which shipment | PK (shipment_id, order_item_id) |
| shipment_events | Tracking timeline | `status`, `provider_status`, location, `occurred_at`. Unique (shipment, provider_event_id) |
| return_requests | Customer returns | `rma_number RET-10001…`, `status return_status`, `reason`, resolution, `refund_amount`. A guard checks ownership, delivery and the return window |
| return_items | Lines being returned | quantity cannot exceed what was bought (across open requests) |
| return_evidence | Photos and video in the `return-evidence` bucket | `storage_path`, mime, size |

### Reviews
| Table | Purpose | Key columns / relations |
|---|---|---|
| reviews | Product reviews | rating 1–5, `status review_status`. **`verified_purchase` is set only by trigger**, from a delivered order line for the same user and product. One review per user per product |
| review_media | Images in the `review-media` bucket | `review_id`, `storage_path` |
| review_votes | Helpful / not-helpful votes | PK (review, user). A trigger maintains the counts |

| discount_targets | Include/exclude rules shared by coupons and offers | exactly one of coupon/offer and one of product/category (includes descendants)/collection |
| coupon_redemptions | Coupon uses | **`order_id` unique**, `status reserved/applied/reversed`, user/email (counts toward limits) |
| offer_redemptions | Offer uses | unique (offer, order), applications, amount |
| campaigns | Campaigns | `status campaign_status`, `channel`, `utm_campaign`, linked coupon/offer, `metrics` jsonb |
| campaign_products / campaign_collections | Campaign links | |
| testimonials | Homepage quotes | `is_published`, sort |

### Analytics, journey and support

|---|---|

### Settings, integrations and ops
| Table | Purpose |
|---|---|
| store_settings | Singleton (`id = true`) holding tax_percentage, tax_inclusive, gst_number, currency, free_shipping_threshold, flat fee, COD rules and fee, return window, reservation TTL, try-on TTL. | integration_configs | Provider × environment with non-secret config, `secret_ref` (the env var name), `status integration_status`, `last_checked_at`, `last_error` |

| tryon_sessions | Try-on runs: status, product/variant, user or anonymous id, provider, source/result paths in `tryon-private`, `expires_at`, `cost_paise`, `latency_ms`, `error_class` |

## RPCs (called with `supabase.rpc`)

| Function | Caller | Notes |
|---|---|---|
| `compute_pricing(items, coupon, user, email, method, provider, state, lock)` | service | The price authority. Returns the `CartTotals` shape plus lines, nudges and errors |
| `quote_cart(cart_id, …)` / `apply_coupon(cart_id, code)` | owner or service | Wrap compute_pricing for a stored cart |
| `place_order(idempotency_key, payload)` | service | Idempotent: the same key always returns the same order (`replayed: true`) |
| `start_payment_attempt` / `record_payment_failure` / `mark_payment_captured` / `reconcile_order_payment` | service | See [PAYMENTS_DATA.md](PAYMENTS_DATA.md) |
| `reserve_inventory` / `release_inventory` / `release_order_inventory` / `commit_order_inventory` | service | Row-locked. No overselling |
| `adjust_inventory(variant, delta, reason, note)` | staff `inventory.write` or service | Manual stock change, written to the ledger |
| `cancel_order(order, reason)` / `release_expired_reservations()` | staff `orders.write` or service / cron | Releases or restocks inventory and reverses redemptions |
| `get_order_tracking(token)` | anon | Returns safe fields only (no email, phone or street) |
| `get_customer_journey(user_id)` | staff `journey.read` | Timeline of events, orders, payment attempts, tickets and try-ons |
| `cleanup_expired_tryon_sessions()` | cron (service) | Returns storage paths for the backend to delete |
| `publish_scheduled_posts()`, `ensure_analytics_partition(month)` | cron | |
| `has_permission(perm)`, `auth_role()`, `is_staff()` | anyone | RBAC helpers used by RLS |

## Seed IDs (deterministic, for `src/data/*`)

| Entity | UUID pattern |
|---|---|
| categories | `10000000-0000-4000-8000-0000000000NN` (01 Clothing, 02 Sneakers, 11 T-Shirts, 12 Shirts, 13 Hoodies, 14 Jackets, 15 Trousers, 21 Low-top, 22 High-top, 23 Runners) |
| collections | `20000000-0000-4000-8000-00000000000N` (1 everyday-basics, 2 new-season, 3 sneaker-edit) |
| products | `30000000-0000-4000-8000-0000000000NN` (01–16, same order as `seed.sql`) |
| variants | `3100PPPP-0000-4000-8000-0000000000VV`, where VV = (colourIndex−1) × sizeCount + sizeIndex (1-based). SKU = `wavy-<CODE>-<COL3>-<SIZE>` |
| offer "3 for ₹999" | `50000000-0000-4000-8000-000000000001` |
| coupons | WELCOME10 `51000000-…-000000000001`, FREESHIP `51000000-…-000000000002` |
| blog posts | `82000000-0000-4000-8000-00000000000N` |
